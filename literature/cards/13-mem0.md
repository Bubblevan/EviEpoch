# Mem0 — 六问研究卡

- **论文：** *Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory*，arXiv:2504.19413v1。
- **原文：** [PDF](<../original/Mem0 - Building Production-Ready AI Agents with Scalable Long-Term Memory.pdf>)
- **版本边界：** 2025 论文的基础/图方案不等同于商业榜 Mem0 v3 或当前开源主分支。

## 01｜针对哪个具体 Memory Failure？

跨会话历史不断增长，窗口无法长期保留用户重要事实；重复或矛盾记忆还会影响连贯性。方法将抽取和更新分成两步，并以图扩展补关系信息。

## 02｜输入、输出和内部状态是什么？

输入为新消息对、已有对话摘要、最近消息（实验 m=10）。抽取器产出候选事实；每项检索最相似旧记忆（s=10），通过 LLM tool calls 选择 ADD、UPDATE、DELETE、NOOP。基础内部状态为可编辑事实与向量库。Mem0g 另抽实体与关系三元组，使用图数据库、实体向量和关系元数据；冲突关系标失效而非物理移除，检索使用实体邻接与语义三元组两条路径。输出为更新后的记忆与供回答器使用的检索上下文。

## 03｜作用于 Add、Manage 还是 Search？

重点为 Add/Manage 的抽取与操作选择，图扩展增加关系 Search。基础方案遇到矛盾可 DELETE；图方案使用失效标记。必须区分二者，不能统一描述成“所有旧信息都覆盖删除”或“全部追加不删”。

## 04｜哪一个消融真正支持创新点？

基础 Mem0 与 Mem0g 比较支持“增加图表示”这一整组机制的效果差异，论文总体报告图版本约 2% 的额外收益，并在时间/开放域上有优势、在另一些类别有取舍。论文没有逐一移除抽取器、相似旧记忆上下文、四操作管理器来隔离创新。相较 Full Context 的 token/latency 降低说明系统取舍，不等于证明每种管理动作都正确。

## 05｜AML 固定 Answer/Eval、同步 Add 下适用什么？

显式管理动作可直接启发参赛系统；但需要把真实变化、纠错、相同支持与用户删除建成不同语义。普通更新应保留历史原始来源，DELETE 用户信息则应跨所有派生索引执行。图/向量默认模型需要改为赛事允许配置；最终返回可回溯源句，不能把派生摘要的答案当成原文证据。

## 06｜相对 EviEpoch 新增什么？

当前 EviEpoch 在 Add 后主要追加 raw/fact；新增是相似事实对照、类型化更新与关系图检索。新项目进一步引入双时间、支持/矛盾/纠正关系和源片段指针，使管理可解释且可还原，不依赖“最新文本替换旧文本”作为全部状态语义。
