# MAGMA — 六问研究卡

- **论文：** *MAGMA: A Multi-Graph based Agentic Memory Architecture for AI Agents*
- **版本：** ACL 2026 Long Paper
- **原文：** [PDF](<../original/MAGMA - A Multi-Graph based Agentic Memory Architecture for AI Agents.pdf>)
- **阅读重点：** §3.2–3.4 图结构、分层检索和写入；§4.5 消融；§6 局限。

## 01｜这篇论文针对哪个具体的 Memory Failure？

针对单一向量/单体记忆把语义相似、时间顺序、因果关系和实体连续性混在一起，导致查询意图与取回关系类型不匹配、噪声子图干扰推理。它提出关系视图解耦：WHY 优先因果、WHEN 优先时间、ENTITY 优先实体链。

## 02｜核心算法的输入、输出和内部状态是什么？

- **输入：** 时间标记的事件流；检索时是自然语言问题。
- **事件节点：** 内容、离散时间戳、稠密向量和属性/实体/上下文元数据。
- **内部状态：** 时变有向多重图，包含语义、时间、因果、实体四类关系视图；时间边构成顺序骨架，实体边维持对象跨时间的同一性。
- **Search：** 查询分析得到意图类别、时间区间、密集/词法表示；多信号融合选锚点，再按边类型和语义相关度做自适应 beam traversal，过滤并排序子图。
- **Add/Manage：** 快路径做事件分段、向量入库、不可变时间骨架更新；慢路径后台用 LLM 在局部邻域推断因果与实体联系。

## 03｜它作用于 Add、Manage 还是 Search？

全链路覆盖，核心是 **Search 的意图路由 + 多图遍历**。写入架构分快慢路径：快速路径不阻塞用户交互，结构推断异步发生。对严格同步 Add 来说，必须确认慢路径未完成时新增记录是否已可被 Search 检索。

## 04｜作者的哪一个消融实验真正支持其创新点？

LoCoMo Table 4 的去关系类型消融：完整 MAGMA Overall 为 0.700；移除 Temporal Backbone / Causal Links / Entity Links 后约为 0.647 / 0.644 / 0.666。Table 5 单图配置的 Overall 均低于 0.60；其中 Temporal Only 在 Temporal 类最好（0.620），Causal Only Overall 最高（0.590），而完整多图达到 Temporal 0.650、Overall 0.700。它支持关系视图互补，尤其时间与因果结构不能互相替代；没有直接测试多图是否比“同样字段、不同存储实现”更有效。

## 05｜在 AML 固定 Answer/Eval、同步 Add 下，哪些机制仍适用？

可迁移查询意图路由、明确的时间排序/过滤，以及时间、因果、实体关系分别作为检索信号；不必按论文方案全量构四图。快路径可帮助满足同步 Add，但图边若在异步慢路径才生成，不能把还不可检索的 Add 当已完成。论文的答案由其生成链路产生，需改为返回证据原文和来源标识。

## 06｜与 EviEpoch 当前代码相比，真正新增了什么？

当前 EviEpoch 以向量相似度融合和邻近原文扩展为主；没有 query intent 路由、时间骨架、因果/实体遍历或稀疏词法锚点。可先比较一条时间字段/实体字段过滤通道，再做意图条件化排序；整套四图会引入抽取、消歧和存储成本，应由消融逐层论证。
